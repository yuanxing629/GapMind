# 论文阅读入口可发现性修复方案

## 1. 背景与目标

当前系统已经具备独立的论文阅读能力，包括论文阅读库、PDF 原文查看、阅读进度、批注以及将当前论文或批注带入课题空间 AI 助手。但是这些能力没有被放在用户最容易发现的位置，导致用户从课题空间进入后，很难知道“文献”管理页之外还有一个真正的“论文阅读”页面。

本方案只解决论文阅读入口和上下文衔接问题，不改变论文阅读的数据模型、PDF 解析流程、证据链路和现有 API 语义。

目标如下：

1. 用户从全局导航可以直接进入“论文阅读”。
2. 用户在某个课题空间的“文献”页面可以直接打开该课题的阅读视图。
3. 用户可以从文献列表的单篇论文操作进入对应阅读页。
4. 从课题空间进入阅读视图时，默认保持当前课题，不要求用户再次选择课题。
5. 在没有论文、没有 PDF、PDF 尚未解析等状态下，入口和下一步动作清晰可见。
6. 桌面端和移动端都能找到入口并完成进入阅读、返回阅读库和返回课题空间的操作。
7. 不新增数据库表，不删除既有路由，不破坏知识、检索、AI 助手和证据视角。

非目标：

- 本次不重写 PDF 阅读器。
- 本次不改变阅读状态、阅读进度、批注和阅读库的后端存储逻辑。
- 本次不把阅读库改造成独立的论文管理域。
- 本次不把“已导入课题的论文”和“已加入阅读记录的论文”强制拆成两个用户流程；保持当前打开论文时按需创建阅读记录的行为。

## 2. 当前实现核对

### 2.1 已存在的路由和能力

前端已经在 `frontend/src/App.tsx` 注册了两条路由：

| 路由 | 页面 | 当前用途 |
|---|---|---|
| `/reading` | `ReadingPage` | 选择课题空间、查看论文阅读库、搜索/导入论文、进入单篇阅读 |
| `/reading/:paperId` | `ReadingPaperPage` | 查看 PDF、保存阅读状态和页码、创建/删除批注、向 AI 助手提问 |

`ReadingPage` 的页面标题是“论文阅读”，其中有“阅读库”和“搜索论文”两个标签页。阅读库中的每一篇论文都有“阅读”按钮；如果论文还没有阅读记录，打开时会先调用加入阅读库接口，再进入单篇阅读页。

`ReadingPaperPage` 已经包含：

- PDF 原文 iframe；
- PDF 缺失时的“上传 PDF 开始阅读”操作；
- PDF 尚未解析时的状态提示；
- 页码输入和阅读状态保存；
- 按页码创建批注；
- 对批注或当前论文询问 AI；
- 返回阅读库、打开 DOI 和 arXiv 外部链接。

因此，当前问题不是功能不存在，而是用户到达这些路由的路径不明显。

### 2.2 当前导航结构

全局侧栏在 `frontend/src/components/AppLayout.tsx` 的主导航中目前只显示：

- 首页；
- 课题空间；
- 知识库。

虽然 `frontend/src/components/layout/navigation.ts` 已经可以识别 `/reading` 为选中状态，但主导航没有对应的菜单项。这会造成“地址栏直接访问时页面存在，正常点击导航时却找不到”的断裂体验。

课题空间侧栏在 `frontend/src/components/layout/navigation.ts` 中包含：

- 概览；
- 文献；
- AI 助手；
- 知识；
- 研究空白；
- 发现；
- 研究中心；
- 动态；
- 设置。

其中“文献”对应 `/workspaces/:id/papers`，其职责是搜索、导入、上传和解析论文，不是阅读页面。

### 2.3 课题文献页当前缺少的操作

`frontend/src/pages/WorkspacePapersPage.tsx` 只渲染论文搜索和 `PapersSection`。

`frontend/src/components/PapersSection.tsx` 的单篇操作目前包括：

- 编辑论文信息；
- 上传 PDF（无全文时）；
- 删除论文。

当前没有“阅读”或“打开 PDF”按钮。即使论文已经上传 PDF，用户仍然需要知道 `/reading` 这个未展示的全局路由，才能继续阅读。

### 2.4 当前上下文传递问题

`ReadingPage` 会使用当前应用状态中的 `currentWorkspaceId` 初始化课题，并提供课题下拉选择。但从 `/workspaces/:id/papers` 跳转到 `/reading` 时，当前课题没有通过 URL 显式传递。

这会带来两个问题：

1. 用户从课题空间点击进入阅读后，无法从链接本身确认阅读视图属于哪个课题。
2. 刷新、复制链接、从新标签页打开或当前应用状态尚未恢复时，可能需要用户再次选择课题。

方案应支持类似 `/reading?workspace_id=<workspaceId>` 的上下文参数，并保持没有参数时的全局选择行为。

## 3. 推荐的产品结构

### 3.1 保留全局阅读入口

在全局侧栏增加一个一级入口：

```text
论文阅读
```

推荐放置位置：

```text
首页
课题空间
论文阅读
知识库
```

理由：

- 论文阅读是用户高频的基础工作面，不应隐藏在知识图谱或文献管理页之后。
- 阅读页可跨课题选择，天然适合放在全局导航。
- 保留现有 `/reading` 路由，改动最小，不需要新增路由层级或后端接口。

图标使用现有 Ant Design 图标体系中的阅读/书籍图标，例如 `ReadOutlined`；菜单文案使用“论文阅读”，避免和课题空间里的“文献”管理混淆。

### 3.2 在课题空间文献页增加上下文入口

在 `WorkspacePapersPage` 页面标题区域增加主操作：

```text
进入论文阅读
```

点击后跳转到：

```text
/reading?workspace_id=<当前课题ID>
```

这个按钮表达的是“阅读当前课题已有论文”，不等同于搜索或导入论文。

按钮显示建议：

- 当前课题存在论文时：正常显示，使用 primary 或次主按钮样式；
- 当前课题还没有论文时：仍然可以显示，但降级为次要按钮，并把用户引导到导入论文操作；
- 当前课题加载失败时：不执行跳转，保持错误提示和重试操作。

推荐的页面头部操作顺序：

```text
进入论文阅读   搜索/导入操作
```

### 3.3 在论文列表增加单篇阅读按钮

在 `PapersSection` 的“操作”列增加一个明确的“阅读”按钮：

```text
[阅读] [编辑] [上传 PDF] [删除]
```

行为：

- 有 `primary_artifact_id`：进入 `/reading/<paperId>`；
- 没有 `primary_artifact_id`：仍允许进入单篇阅读页，由阅读页展示“上传 PDF 开始阅读”；
- 如果产品希望减少无效跳转，也可以在按钮旁显示“待上传”，但不能让用户误以为这篇论文无法进入阅读流程。

按钮文案必须是“阅读”，不要使用只有图标的按钮。表格在移动端横向滚动时，操作列仍应保留可识别的标题或 tooltip。

单篇入口和页面级入口的区别：

| 入口 | 目标 | 是否携带课题上下文 |
|---|---|---|
| 全局侧栏“论文阅读” | 打开阅读库 | 可使用当前课题或用户选择课题 |
| 课题文献页“进入论文阅读” | 打开当前课题的阅读库 | 必须携带 `workspace_id` |
| 论文行“阅读” | 直接打开单篇论文 | 由论文自身的 `workspace_id` 决定 |

### 3.4 概览页增加低成本辅助入口

作为第二优先级，在 `WorkspaceOverviewPage` 的课题文献统计卡或“下一步”区域增加：

- 有论文时：`继续阅读论文`；
- 无论文时：继续显示现有的 `添加文献`。

该入口直接跳转到 `/reading?workspace_id=<当前课题ID>`。

本入口不需要新增后端接口，因为概览页已经知道课题和论文统计。不要在本次修复中为了展示“最近阅读”而新增额外聚合查询；如果后续需要最近阅读排序，再单独设计阅读状态查询和性能策略。

## 4. 具体实现方案

### 4.1 路由和 URL 契约

保留现有路由：

```text
/reading
/reading/:paperId
```

为阅读库增加可选查询参数：

```text
/reading?workspace_id=<workspaceId>
```

参数规则：

1. `workspace_id` 为空时，保持当前行为：使用应用状态中的当前课题；如果仍没有当前课题，则使用课题列表的第一个课题或提示用户选择。
2. `workspace_id` 有值时，优先使用 URL 参数初始化阅读库。
3. URL 参数对应不存在、无权访问或已删除的课题时，不应静默展示其他课题的数据。应显示“课题空间不存在或无权访问”，并提供返回课题空间列表的操作。
4. 用户在阅读页切换课题时，更新 URL 参数，保证刷新和复制链接后上下文一致。
5. 单篇阅读页不需要额外增加 `workspace_id` 参数；后端返回的论文所属课题是唯一上下文来源。

建议使用 React Router 的 `useSearchParams`，不要手动拼接和解析完整 URL。

### 4.2 全局侧栏实现

修改文件：

```text
frontend/src/components/AppLayout.tsx
```

实现要点：

1. 在 `primaryNavigation` 增加 `/reading` 菜单项。
2. 使用 `ReadOutlined` 或项目中已有的同类图标。
3. 在 `openNavigation` 中为 `/reading` 保持直接导航，不附加错误的生命周期模式参数。
4. `selectedGlobalKey` 已经能将 `/reading` 和 `/reading/:paperId` 标记为 `/reading`，需要保留这一行为。
5. 侧栏折叠时保留图标、无障碍 label 和 tooltip；展开时显示“论文阅读”。
6. 不要把阅读入口放进“知识库”子菜单，也不要把 `/reading` 改造成知识图谱的子路由。

如果主导航数组目前是组件内私有常量，不需要为了测试而抽取复杂的导航注册系统；只做最小的菜单项添加即可。

### 4.3 课题文献页实现

修改文件：

```text
frontend/src/pages/WorkspacePapersPage.tsx
frontend/src/components/PapersSection.tsx
```

页面级按钮：

1. 在 `WorkspacePapersPage` 中使用 `useNavigate`。
2. 页面级“进入论文阅读”跳转到带 `workspace_id` 的 `/reading`。
3. 页面加载态下不因为 workspace 对象暂未准备好而产生错误链接。
4. 论文为空时，按钮仍可见，但文案或辅助说明应提示先导入论文。

单篇按钮：

1. 给 `PapersSection` 增加 `useNavigate`。
2. 使用论文记录自身的 `id` 跳转到 `/reading/<paperId>`。
3. 不在前端根据标题、DOI 或 label 查找和拼接论文 ID。
4. 不在点击前重复请求阅读库列表；单篇阅读页会负责获取阅读详情，打开时由既有逻辑按需创建阅读记录。
5. 删除按钮、编辑按钮和上传 PDF 按钮行为保持不变。

如果组件测试难以直接渲染 React Router，可以把单篇路径构造抽为一个非常小的纯函数并测试；不要为了一个路径引入新的状态管理抽象。

### 4.4 阅读库上下文实现

修改文件：

```text
frontend/src/pages/ReadingPage.tsx
```

建议状态优先级：

```text
URL workspace_id
    > 当前应用 workspace_id
    > 课题列表的第一个可用课题
    > 空状态提示用户选择
```

实现时需要注意：

1. 初始化时读取 URL 参数，不能只在首次 render 时读取一次后永远忽略变化。
2. 当 URL 中的课题不存在时，不能回退到另一个课题并继续显示数据；应先验证课题列表。
3. 课题切换后重新加载论文列表和阅读状态，并同步 URL。
4. 加载时显示课题和论文数据的稳定 loading 状态，避免先显示旧课题数据再切换。
5. `readingApi.list` 和 `paperApi.list` 继续使用同一个 `workspace_id`，避免阅读库的论文和阅读状态来自不同课题。
6. 保留当前“所有课题论文可出现在阅读库，未建立阅读记录的论文在打开时按需加入”的现有行为，除非后续产品明确要求区分“全部论文”和“我的阅读清单”。

建议把 `workspace_id` 作为 URL 的唯一参数名，和后端阅读列表 API 的参数名保持一致，避免出现 `workspaceId`、`workspace_id` 两套外部链接格式。

### 4.5 阅读页返回路径

修改文件：

```text
frontend/src/pages/ReadingPaperPage.tsx
```

当前“返回阅读库”直接跳转 `/reading`。第一版可以保持该行为，依靠当前应用状态恢复课题；更稳妥的实现是把来源课题带回去：

```text
/reading?workspace_id=<paper.workspace_id>
```

推荐采用后者，原因是：

- 论文详情已经返回 `workspace_id`；
- 用户从某个课题打开后返回，不应该被切换到其他课题；
- 页面刷新或状态丢失时仍能恢复阅读上下文。

DOI、arXiv、AI 助手和批注功能不做行为变化。

## 5. 交互状态与文案

### 5.1 全局没有当前课题

进入 `/reading` 后：

- 侧栏“论文阅读”保持选中；
- 页面显示课题选择器；
- 显示“请先选择一个课题空间”；
- 不请求无 workspace 的论文数据；
- 不显示看起来像真实论文的空表格行。

### 5.2 课题没有论文

页面应同时给出两个清晰动作：

```text
搜索论文
上传 PDF / 手动添加
```

建议说明：

```text
当前课题还没有论文。先导入或上传论文，之后可以在这里阅读 PDF、记录进度和添加批注。
```

### 5.3 论文没有 PDF

允许用户进入单篇阅读页，但明确说明：

```text
这篇论文还没有 PDF 原文
上传 PDF 开始阅读
```

如果存在 DOI 或 arXiv 链接，继续显示外部原文链接。不要把缺少本地 PDF 显示成“论文不存在”。

### 5.4 PDF 正在解析

阅读页允许先看 PDF，并显示：

```text
原文可以先阅读；解析完成后，这篇论文才会参与课题空间检索和有依据的 AI 回答。
```

该状态提示与阅读入口修复无关，不应因为本次导航改动被删除或弱化。

### 5.5 移动端

移动端的优先级是确保入口可见和操作可触达：

1. 折叠侧栏中显示阅读图标和 tooltip/aria-label。
2. 页面头部的“进入论文阅读”按钮允许换行或占满可用宽度。
3. 论文表格保持横向滚动，阅读按钮不能被默认隐藏在不可发现的更多菜单中。
4. 单篇阅读页继续采用现有的 PDF 上、批注侧栏下布局。
5. “返回阅读库”按钮在窄屏下保留可读文字，不只显示箭头图标。
6. PDF iframe 高度使用已有移动端样式，不能因为增加入口而压缩到不可用高度。

## 6. 前端测试方案

### 6.1 导航纯函数测试

修改：

```text
frontend/src/components/layout/navigation.test.ts
```

增加以下断言：

1. `selectedGlobalKey("/reading")` 返回 `/reading`。
2. `selectedGlobalKey("/reading/paper-1")` 返回 `/reading`。
3. `selectedGlobalKey("/workspaces/ws-1/papers")` 仍然不会误标记为 `/reading`。
4. 如增加上下文 URL 构造函数，验证 workspace ID 被正确编码并生成 `/reading?workspace_id=...`。

### 6.2 阅读库上下文测试

如果项目已有页面测试工具，则为 `ReadingPage` 增加测试；否则优先测试抽出的最小纯逻辑：

| 场景 | 预期 |
|---|---|
| URL 有合法 `workspace_id` | 默认加载该课题 |
| URL 无参数但 store 有当前课题 | 加载当前课题 |
| 两者都没有但课题列表非空 | 选择第一个课题，并更新上下文 |
| URL 指向不存在课题 | 不展示其他课题数据，显示错误/无权提示 |
| 用户切换课题 | 重新加载对应论文和阅读状态，URL 同步 |

### 6.3 文献列表入口测试

为 `PapersSection` 或其路径逻辑增加测试：

1. 每一行显示“阅读”按钮。
2. 点击阅读按钮跳转到对应 `paper.id` 的 `/reading/<paperId>`。
3. 没有 PDF 的论文仍然可以进入阅读页，上传引导由阅读页负责。
4. 编辑、上传和删除按钮仍然显示并保持原行为。
5. 论文标题、DOI 和 label 不会被用来替代真实 `paper.id`。

## 7. 手工验收清单

### 7.1 桌面端

使用真实课题空间验证：

- [ ] 全局侧栏出现“论文阅读”。
- [ ] 当前位于 `/reading` 或 `/reading/:paperId` 时，侧栏正确高亮“论文阅读”。
- [ ] 从全局侧栏进入后能看到课题选择器和论文阅读库。
- [ ] 从课题空间“文献”页点击“进入论文阅读”后，默认仍是当前课题。
- [ ] 直接从论文列表点击“阅读”可以打开对应论文。
- [ ] 从单篇阅读页返回时仍回到原课题阅读库。
- [ ] 有 PDF 的论文能显示 PDF；无 PDF 的论文显示上传引导。
- [ ] 阅读状态、页码和批注功能没有回归。
- [ ] DOI/arXiv 外部链接和“询问这篇论文”仍可用。

### 7.2 隔离和链接行为

## 9. 风险与控制

### 风险一：阅读库和课题文献列表的语义重复

控制方式：

- 全局导航使用“论文阅读”；
- 课题空间使用“文献”，明确其导入/解析职责；
- 页面描述中说明“文献”是管理入口，“论文阅读”是 PDF、进度和批注入口。

### 风险二：切换课题时显示旧数据

控制方式：

- workspace ID 变化时同时重置 loading 和列表；
- 在新请求完成前不保留旧课题的可操作论文行；
- URL、store 和请求参数使用同一个最终 workspace ID。

### 风险三：非法 workspace 参数导致跨课题展示

控制方式：

- 先从有权限的 workspace 列表校验 URL 参数；
- 校验失败时停止加载论文；
- 不使用 `response.items[0]` 作为非法参数的静默回退目标。

### 风险四：表格操作列在移动端不可见

控制方式：

- 保留明确的“阅读”文本按钮；
- 设置合理的操作列宽度；
- 在手工验收中用窄屏测试横向滚动和点击区域。

### 风险五：阅读页返回后丢失课题

控制方式：

- 返回链接带上论文详情中的 `workspace_id`；
- 阅读库从 URL 优先恢复上下文；
- 为返回路径和 URL 参数增加测试。

### 风险六：引入不必要的后端变更

控制方式：

- 本方案复用现有 `/reading`、`/reading/:paperId` 和阅读 API；
- 不新增数据库表和迁移；
- 不改变现有阅读接口响应结构；
- 只有在发现当前后端无法验证 workspace 归属时，才单独提出后端修复，不在入口修复中隐式扩大范围。

## 10. 完成标准

本修复只有在以下条件全部满足后才算完成：

1. 用户无需记忆 URL，就能从全局导航进入论文阅读。
2. 用户在课题空间“文献”页能一键进入当前课题的阅读库。
3. 用户在论文列表中能直接打开任意论文的阅读页。
4. 阅读库和单篇阅读页不会因为入口跳转丢失课题上下文。
5. 无 PDF、解析中、无论文和非法 workspace 等状态都有明确反馈。
6. `/reading`、`/reading/:paperId` 及现有论文导入、PDF 上传、解析、批注、AI 提问能力均保持可用。
7. workspace 隔离、移动端可用性和导航高亮均通过手工验收。
8. 前端测试、typecheck、build 和 lint 全部通过。
9. 修改前端 API 的情况才执行 `npm run gen:api`；不手写自动生成类型文件。

## 11. 推荐的最小交付范围

如果需要先快速修复用户当前遇到的“找不到论文阅读入口”问题，建议第一轮只实施以下三项：

1. 全局侧栏新增“论文阅读”。
2. 课题文献页新增“进入论文阅读”，并带上 `workspace_id`。
3. 论文列表每行新增“阅读”。

这三项不需要后端改动，不需要数据库迁移，也不需要生成新的 OpenAPI 类型。完成后再根据真实使用反馈决定是否增加概览页“继续阅读”和更细的阅读状态分组。
